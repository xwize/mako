# Mako

This workspace uses Mako: a kanban board plus fixed agent slots, each with its own git worktree.

- Workspace root: {root}
- Project repo: {project}/ (main checkout, branch `{base}`).
- Issues: cards like `{prefix}-0001` in kanban/open and kanban/closed, shown on kanban/board.md (Obsidian).
- Lifecycle: Backlog -> In Progress (claim) -> Done (close). Closing merges the issue branch into
  `{base}` (or the card's `merge_to` branch), so nothing reaches Done unmerged, except spikes,
  which never merge (their branch is kept). `discard_issue` drops an issue without merging.
- Mako owns kanban/. Never edit or move those files yourself; use the mako tools. `edit_issue`
  changes a card while it is in the Backlog.
- Cards marked `human: true` are the user's own tasks: agents can't claim, close or release them.
- Cards a worker slot creates start `approved: false`, and nobody can claim them until the user
  approves them. Cards the orchestrator or the user create are approved from the start.
- More detail by topic: the `guide` tool with `topic` (`review`, `hooks`, `cli`), or `mako guide <topic>`.
